# Findit 产品视角审查报告

- **审查对象**：Findit（Flutter UI + flutter_rust_bridge Rust 核心的隐私优先本地收纳应用）
- **审查视角**：产品体验与功能完整性（三视角并行审查之一）
- **审查人**：产品审查员
- **审查日期**：2026-02（提交 `02a1551` 之后的工作区状态，分支 `main`）
- **审查方式**：静态代码审查（`lib/`、`rust/`、`android/`、`ios/`、`web/`、`docs/`、`test/`、`integration_test/`）+ 文档核对 + 构建产物核对（`build_apk.log` 显示最近一次 `assembleRelease` 成功，产物 83.3MB）。**未进行真机运行验证**，交互结论基于代码路径推演，建议发布前补充真机走查（见 §6）。

## 1. 产品定位与已实现功能核对

定位：**隐私优先的家庭自托管收纳定位安卓应用**——数据全存本地 SQLite、离线可用、无账号无服务端。README 声明的功能与代码实现核对如下：

| README 声明 | 实现情况 | 证据 |
| --- | --- | --- |
| 层级收纳：存储单元 → 收纳箱 → 物品 | ✅ 完整实现（三级页面 + 空态引导 + 计数徽章） | `units_page.dart` / `boxes_page.dart` / `items_page.dart` |
| 二维码标签 `findit://box/{slug}` | ⚠️ 部分实现：App 内生成/导出/扫码闭环可用；**未注册系统级深链**（见 F1） | `box_qr_sheet.dart` / `scan_page.dart` / AndroidManifest |
| AI 快速录入及修订（Ollama / OpenAI 兼容） | ✅ 实现（四层容错解析、预览可编辑、意图切换、语音输入） | `quick_add_page.dart` / `core/ai/parse.rs` / `core/ai/apply.rs` |
| 智能搜索（关键词 + 语义双通道、相似度百分比、无 AI 降级） | ✅ 实现（关键词先出、向量并发、3s 超时降级、去重语义优先） | `search_page.dart` / `core/search/hybrid.rs` |
| 照片留档（缩略图、大图预览） | ✅ 实现（1600px/q82 主图 + 256px/q70 缩略图、删除、替换） | `photo_viewer_page.dart` / `core/photo.rs` |
| 分类标签 | ✅ 基础实现（多选 + 行内新建） | `items_page.dart` |
| 备份/恢复（zip、原子替换、回滚、保留最近一份旧副本） | ✅ 实现（校验链 + zip-slip/bomb 防护 + 快照剔除 API Key） | `core/backup/*` / `settings_page.dart` |
| 全中文界面、深色模式 | ✅ 实现（双主题 ThemeExtension 色板） | `theme.dart` |
| 无 AI 降级 | ✅ 实现（快速录入报错、搜索降级关键词） | `ai.rs` / `search_page.dart` |

整体评价：**核心功能链完整、工程质量高**（错误码统一中文化、空态/加载/失败三态齐全、删除二次确认、备份恢复安全性考虑周到），属于"功能正确但体验细节有若干断点"的阶段。

## 2. 问题清单（按严重度分级）

### 2.1 高严重度

#### F1【高 / P1】二维码标签缺少系统级深链注册，"扫码直达"闭环在物理世界断裂

- **证据**：`android/app/src/main/AndroidManifest.xml` 无 `findit://` scheme 的 `<intent-filter>`；`ios/Runner/Info.plist` 无 `CFBundleURLTypes`；`lib/src/pages/scan_page.dart` 仅在 App 内解析二维码；README.md L7-8 宣传"可打印张贴；扫码直达箱内清单"。
- **问题**：打印出来的标签被任意手机相机 / 通用扫码 App 扫描时，系统无法唤起 Findit（无 scheme 声明），也不会跳转到对应收纳箱。只有先打开 Findit 再用 App 内扫码页才能到达——这正是标签最典型的物理使用场景（贴在箱子上，随手扫）。家人/访客扫码的场景完全不可用。
- **建议**：
  1. Android 注册 `<intent-filter>` 处理 `findit://box/*`（`android:scheme="findit"` + `android:host="box"`），`MainActivity` 或 Flutter 侧解析 deep link 直达 `ItemsPage`；
  2. iOS 同步补 `CFBundleURLTypes`（若 iOS 在路线图内）；
  3. 至少在 README 中明确"标签需使用 Findit 内扫码"，避免用户预期落差。

#### F2【高 / P1】AI"修改物品"预览不展示将被修改的目标物品，存在改错对象风险

- **证据**：`lib/src/pages/quick_add_page.dart` 预览区（L349-357）只有 `target_query` 输入框，没有展示解析/检索到的目标物品；`rust/src/core/ai/apply.rs` L130-134 取关键词搜索的**第一个命中**作为修改对象。
- **问题**：存在同名/相似物品（如两把"螺丝刀"、两个"充电宝"）时，用户确认后可能改错对象，且预览阶段完全不可见——"先预览后入库"的设计初衷（核对无误再执行）在修改场景被绕过。命中物品与用户意图不符时，用户只有在保存后进入对应箱才能发现。
- **建议**：预览阶段先按 `target_query` 检索并展示命中物品（名称 + 所在箱/单元 + 数量 + 命中数），若多个候选则提供选择；或至少在确认按钮文案中带出"将更新「名称」（当前在「单元/箱」）"。

### 2.2 中严重度

#### F3【中 / P1】物品无法在普通编辑界面移动收纳箱，核心能力依赖 AI

- **证据**：`lib/src/pages/items_page.dart` 的 `_ItemFormSheet`（L382-835）无"所在收纳箱"字段；后端 `rust/src/api/items.rs` 的 `update_item` 支持 `box_id` 参数但 UI 从未使用；移动只能通过 AI 快速录入的 modify 意图实现。
- **问题**：收纳场景中"把东西从 A 箱挪到 B 箱"是最高频操作之一。未配置 AI 的用户完全没有移动物品的途径（AI 不可用时报"AI 未配置"）。快速录入入口对无 AI 用户形同虚设（见 F6 补充建议）。
- **建议**：编辑表单增加"所在收纳箱"选择器（至少支持本单元内跨箱选择，若能跨单元更佳）；无 AI 时快速录入降级为普通表单（建档/改箱/改数量均可手填），而不是直接报错。

#### F4【中 / P2】分类缺少管理入口：重命名/删除 API 存在但 UI 不可达

- **证据**：`rust/src/api/categories.rs` 提供 `rename_category` / `delete_category`，但 UI 仅 `items_page.dart` L457-471 的行内新建；无分类管理页。
- **问题**：误建、拼错或过时的分类无法清理；分类作为搜索维度（关键词搜索含分类名）会持续产生噪音；分类体系无法维护。
- **建议**：新增分类管理页（列表 + 重命名 + 删除，删除时提示并处理关联物品的分类移除），或在设置页提供入口。

#### F5【中 / P2】搜索页体验断点：结果不直达物品、无缩略图、语义提示误导

- **证据**：`lib/src/pages/search_page.dart` `_openResult`（L103-113）点击结果仅打开整个 `ItemsPage(boxId)`，需在箱内再找目标物品；`_ResultCard`（L362-427）不渲染 `SearchResult.photoPath` 缩略图；`_IdleHint` L245 无条件显示"语义搜索已上线"。
- **问题**：①"找到即直达"的预期落空，大箱内仍需滚动查找；②结果卡片无照片，视觉辨识弱；③未配置 AI 时提示语仍宣传语义搜索，属误导（此时为纯关键词）。
- **建议**：①搜索命中后直达物品（进入箱页并高亮定位，或新增物品详情页）；②结果卡片渲染缩略图；③根据 `AiStatus.configured` 动态显示语义提示。

#### F6【中 / P2】快速录入解析期无取消/超时兜底，局域网黑洞地址可致分钟级假死

- **证据**：`rust/src/core/ai/client.rs` L16-17 对话超时 60s、网络错误重试 2 次（退避 1s/3s）；`rust/src/api/ai.rs` `parse_via_ai`（L163-191）最多两次 chat 调用（解析 + 修复重试）；`lib/src/pages/quick_add_page.dart` `_Phase.parsing` 阶段按钮禁用且**无取消入口**。
- **问题**：用户把服务地址配错为不可达但可挂起的地址（如真机填了模拟器地址 `10.0.2.2`）时，"解析中…"可能持续数分钟且无法取消；对普通家庭用户是典型的"卡死"体验。错误卡片（L504-537）也只有"重试"，没有"去设置检查"引导。
- **建议**：①解析中提供"取消"；②快速录入场景使用更短超时（如 15-20s）；③AI 未配置/连接失败的错误卡片增加"前往 AI 设置"行动按钮。

#### F7【中 / P2】建档时不能直接拍照，录入+留档被拆成两步

- **证据**：`lib/src/pages/items_page.dart` L726-733 明确提示"保存物品后可在编辑页拍照留档"；创建表单（`_ItemFormSheet` 新建态）无照片区。
- **问题**："登记一件东西并拍照"是收纳留档的高频连续动作，两步操作增加摩擦；用户可能忘记回来补拍。
- **建议**：创建表单直接支持拍照/选图；或保存成功后自动进入该物品的编辑态以便立即补拍。

### 2.3 低严重度

#### F8【低 / P3】无删除撤销/回收站，级联删除不可挽回

- **证据**：`lib/src/widgets/common.dart` `confirmDelete` 仅二次确认；`rust/src/core/repo/units.rs` L132-178 级联删除单元下全部箱与物品（含照片清理）。
- **问题**：收纳数据多为长期积累，误删整单元（如手指误触）无任何挽回手段；虽有二次确认，但无"最后防线"。
- **建议**：①SnackBar 级"撤销"（延迟删除）；②或软删除/回收站（与备份策略协同）。

#### F9【低 / P3】物品登记/更新时间从未展示

- **证据**：`Item` 模型携带 `createdAt` / `updatedAt`（`lib/src/rust/api/model.dart` L280-296），但列表卡片与编辑页均不显示。
- **问题**：用户无法得知物品何时登记、最近何时更新，降低"档案感"；也难以及时发现过期信息。
- **建议**：物品卡片副标题或详情中展示登记/更新时间。

#### F10【低 / P3】备份导出交互与文档不一致，取消分享即丢失备份

- **证据**：`lib/src/pages/settings_page.dart` L172-187 导出到暂存目录后经**系统分享面板**移交，无论成功/取消都删除暂存文件；README.md L70-71 却写"经系统文件选择器保存"。
- **问题**：①用户取消分享时备份被静默删除，SnackBar 仅提示"未保存（已取消分享）"，容易误以为已备份；②分享面板并非所有设备都提供"保存到文件"目标；③文档与行为不一致，会误导用户。
- **建议**：①提供"保存到指定目录"直存路径（file_picker save 或 SAF），分享作为附加选项；②取消分享时保留暂存文件并提示存放位置；③同步修订 README。

#### F11【低 / P3】品牌残留：默认启动图标、默认 web manifest、模板描述未定制

- **证据**：`android/app/src/main/res/mipmap-*/ic_launcher.png` 为 Flutter 默认图标；`web/manifest.json` 为模板内容（`"A new Flutter project."`、默认蓝色主题）；`pubspec.yaml` L2 描述同为模板。
- **问题**：安装后图标无辨识度；Web 目标若启用则品牌完全未定制（虽 Android 优先，但仓库含 web/ 目录）。
- **建议**：定制 launcher 图标；同步 pubspec 描述与 web manifest（名称/图标/主题色）；或在文档中明确"仅 Android 目标，其余平台目录为脚手架"。

#### F12【低 / P3】iOS 权限描述缺失（若计划支持 iOS）

- **证据**：`ios/Runner/Info.plist` 无 `NSCameraUsageDescription` / `NSMicrophoneUsageDescription` / `NSPhotoLibraryUsageDescription`，也无深链 URL Types。
- **问题**：iOS 构建后调用相机/麦克风/相册会直接崩溃或被拒审。
- **建议**：若 iOS 在路线图内补齐；否则在 README 明确"当前仅支持 Android"。

#### F13【低 / P3】AndroidManifest 中文注释乱码、namespace/applicationId 不一致

- **证据**：`android/app/src/main/AndroidManifest.xml` 中文注释呈乱码（文件编码问题）；`android/app/build.gradle.kts` 中 `namespace = "com.example.findit"` 而 `applicationId = "com.kurikana.findit"`（`MainActivity.kt` 位于 `com/example/findit/`）。
- **问题**：工程卫生问题（不影响运行，但影响维护与发布审计）。
- **建议**：修正 manifest 编码；统一 namespace 与源码包路径或文档说明原因。

#### F14【低 / P4】无自动备份/备份提醒

- **证据**：备份仅设置页手动触发（`settings_page.dart`）；无周期提醒。
- **问题**：隐私本地方案下，数据丢失风险完全依赖用户自觉；手机丢失/误卸载即全部数据风险。
- **建议**：导出成功后的"下次提醒"、定期备份提醒，或接入 Android Auto Backup（配合排除敏感设置）。

### 2.4 功能增强建议（Roadmap，不视为缺陷）

1. **物品排序/置顶**：当前三级列表均按名称排序（`repo/items.rs` L133-134 `ORDER BY name`），无法自定义顺序或置顶常用物品；
2. **批量操作**：批量移动/删除/改分类（对收纳整理场景价值高）；
3. **分类浏览视图**：按分类聚合查看所有物品（当前仅搜索时按分类命中）；
4. **多箱二维码批量导出**：一次导出多个箱的标签页（当前逐箱操作）；
5. **关于页**：版本号、许可证（MIT）、帮助/FAQ、数据目录说明；
6. **无 AI 快速录入降级表单**（同 F3）：让"一句话录入"入口对所有用户可用。

## 3. 正向亮点（产品层面）

- **空态引导完备**：三级页面 + 搜索均有引导文案与行动按钮（`widgets/common.dart` `EmptyState`），新手友好；
- **错误体验统一**：全部业务错误经 `friendlyErrorMessage` 转为中文可读提示（`errors.dart`），含"重名""未找到""AI 未配置"等细分；
- **AI 降级策略成熟**：搜索并发先出关键词、查询向量 3s 超时、启动后台回填静默失败（`search_page.dart` / `api/ai.rs`），未配置 AI 时基础功能不受影响；
- **备份恢复安全设计**：校验链（zip-slip/bomb/版本/完整性）、原子替换、失败回滚、旧副本保留、API Key 不随备份分发（`core/backup/*`），对"隐私优先"定位是强加分项；
- **删除安全**：单元/箱/物品删除均二次确认且文案明确级联影响；照片删除同样确认；
- **语音输入**：中文优先、失败自动回退系统语言、不可用时提示不阻塞（`quick_add_page.dart` L171-229）；
- **主题一致性**：亮/暗双主题色板统一（`theme.dart`），扫码页/大图页沉浸式设计有质感。

## 5. 移交线索（供汇总报告与其它视角参考）

- **产品 ↔ 安全**：备份快照会剔除 API Key（`core/backup/export.rs` `scrub_api_key`），但 App 内 `app_settings` 明文存储 AI API Key；且 README 声明"AI API Key 不会写入备份文件"——产品侧认可该行为，安全视角可评估明文存储与剪贴板暴露；
- **产品 ↔ 性能**：`items_page.dart` L56-64 对每件有照片的物品**串行**解析照片路径，箱内照片多时列表刷新可能明显变慢（产品上表现为"打开箱慢"）；搜索页语义通道全库扫描向量（`core/search/hybrid.rs` L78-98），物品量大时向量重排耗时——均建议在性能报告中评估并回填产品建议；
- **产品 ↔ 汇总**：F6（解析期长等待）与 F10（备份导出分享面板）涉及交互与可用性，建议汇总报告在"易用性"章节合并呈现。

## 6. 审查限制

- 未进行真机/模拟器运行验证；相机、语音、分享面板、文件选择器等系统交互行为基于代码路径推演，建议发布前执行一次完整真机走查（含：新建单元→建箱→二维码导出→外部相机扫描标签→AI 建档/修订→无 AI 降级→备份/恢复）。
- 未执行 `flutter analyze` / `cargo test`（属工程门禁，非产品视角职责）；如汇总需要可另行验证。
